# IRIS Database Blueprint v1.0

> **Status:** Frozen (Version 1.0)  
> **Project:** IRIS - Cloud-Based Academic Resource Retrieval System  
> **Purpose:** This document serves as the single source of truth for the IRIS database architecture. Any future changes should only be made if the project requirements change.

---

# 1. Project Scope

## Objective

Develop a Telegram Bot that enables MCA students to retrieve academic resources through a guided button-based navigation system.

---

## Constraints (Frozen)

- Single MCA Department only.
- Four semesters.
- Less than 100 academic resources.
- Less than 50 concurrent users.
- PostgreSQL as the database.
- Telegram Private Channel used for storing PDFs.
- Telegram `file_id` used to retrieve files.
- Button navigation is the primary interface.
- NLP is a future enhancement and **does not affect the database design**.
- Admin Panel will be developed later for resource management.

---

# 2. System Architecture

```text

    │
    ▼

    │
    ▼

    │
    ▼

    │
    ▼

```

### Responsibilities

### Telegram

- User Interface
- Stores PDFs

### Python Backend

- Handles navigation
- Queries PostgreSQL
- Sends files back to Telegram

### PostgreSQL

- Stores metadata
- Stores subjects
- Stores Telegram File IDs

# 4. Database Design

## Table 1 : `subjects`

### Purpose

Stores every university subject exactly once.

| Column | Type | Description |
|---------|------|-------------|
| id | SERIAL | Primary Key |
| semester | INTEGER | Semester Number |
| subject_code | VARCHAR(25) | University Subject Code |
| subject_name | VARCHAR(255) | Subject Name |

---

## Table 2 : `resources`

### Purpose

Stores **every downloadable file** available in IRIS.

**One row = One downloadable file**

| Column | Type | Description |
|---------|------|-------------|
| id | SERIAL | Primary Key |
| category | VARCHAR(50) | Main category |
| subcategory | VARCHAR(80) | Navigation branch |
| subject_id | INTEGER | FK → subjects.id (Nullable) |
| semester | INTEGER | Nullable |
| year | INTEGER | Nullable |
| module | INTEGER | Nullable (Notes only) |
| internal_exam | INTEGER | Nullable (Internal Exam only) |
| title | VARCHAR(255) | Display Name |
| file_name | VARCHAR(255) | Original uploaded filename |
| telegram_file_id | TEXT | Telegram File ID |
| uploaded_at | TIMESTAMP | Creation Timestamp |

### Notes

Not every resource requires every field.

Examples:

- Placement Materials have no semester.
- Resume Templates have no subject.
- Notes have modules but no year.
- Semester Papers have year but no module.
- Internal Papers have year + internal number.

### Additional Notes

- `title` is the name shown to students inside the Telegram bot.
- `file_name` stores the original uploaded filename for easier administration and debugging.
- `telegram_file_id` is the permanent Telegram identifier used to retrieve the file.

# 9. Design Principles (Frozen)

These principles should remain unchanged unless project requirements change.

1. The menu hierarchy is fixed in code.
2. Academic resources are stored in PostgreSQL.
3. One database row represents one downloadable file.
4. Subjects are stored once and referenced everywhere.
5. Telegram Private Channel is the storage backend.
6. No database redesign without a genuine requirement change.
7. NLP will use the existing filters and database; it will not require redesigning the schema.
